The workspace shows completion formula, daily UTC start-date trend, incident type/severity, available/excluded reports and reasons, units, window, GPS gaps, missing/invalid samples and flights without coverage. No started flights means unavailable completion; no valid GPS segments means unavailable distance. Registry-only search/status filters do not silently change the all-started analytics denominator. Source drill-down retains date/UAV/mission scope; report navigation retains the complete original registry query.

## Reproduce browser fixture

Install `playwright-core` in a temporary directory (no repository dependency change), then run from the repository root:

```sh
PLAYWRIGHT_MODULE=/tmp/droneops-browser-check/node_modules/playwright-core \
  node scripts/checks/analytics-browser.cjs
```

The script starts its own Next.js/backend fixture at 127.0.0.1 ports 3188/5188 and closes them afterward. Use unused ports; the default Chrome executable is the macOS Google Chrome application. Set `CHROME_EXECUTABLE` on another host. No real account is needed.

Mobile browser results from earlier in the session are withdrawn from the current scope. The retained browser fixture covers analytics only; see the scope decision in `mobile/README.md`.
