27 [p] 1. System Design
28 [p] 1.1 System Architecture
29 [p] DroneOps Intelligence uses a Next.js/React Web application, an ASP.NET Core API, application services, EF Core/Npgsql persistence and PostgreSQL. A telemetry gateway supplies normalized MAVLink-derived samples, and SSE delivers authorized live updates. Backend adapters provide media storage, email and AI integration. Low-level UAV flight control remains external.

Backend remains authoritative for authorization and state. | 2 | API + Application | JWT/canonical roles, DTO validation, business services and outcome errors. Controllers delegate business operations to services; the composition root configures persistence and external adapters. | 3 | Persistence + Domain | EF entities/repositories plus Npgsql stores. Application depends on repository interfaces in Persistence and entities in Domain. | 4 | PostgreSQL / media | Transactional domain records; proposed request/evidence storage. Private user media uses protected backend read/upload and short-lived access; no public server secret. | 5 | Integration gateway / SSE | Normalized sample HTTP endpoint exists. Raw MAVLink adapter and background loss timer remain gaps; latest snapshot and SSE support frontend monitoring. | 6 | External AI / email | Configured outbound calls with bounded timeout, provenance and error handling. AI advice cannot approve missions.

52 [p] The approval transaction checks the mission, request identity, record scope and current validation evidence before applying the accepted metadata and ordered waypoints. It records the decision and closes the request in the same transaction. Any failure rolls back the complete operation. Rejection updates only the request and decision, preserving current mission content and prior approval. A stale or conflicting request returns 409. Notification delivery follows the committed decision.
53 [p] Indexes support ordered mission waypoints, pending requests, latest mission telemetry, incident status and recipient alerts. Ingestion uses an idempotency key, while decisions use a unique request identity and terminal-state check. Backend authorization protects mission, history, media and streaming operations.

96 [p] 3.3 Post-flight History and Reporting
97 [p] PostFlightService provides history queries, report generation, telemetry playback, mission incidents and operational analytics. Aggregation uses authorized persisted samples and UTC coverage windows. Missing metrics remain null. Mission completion follows the external execution event; it is not a browser flight-control command.

107 [p] 3.4 AI-assisted Mission Assessment
108 [p] IAIService.GenerateMissionSuggestionAsync and OpenAIService provide the external AI adapter. MissionSuggestionService prepares and persists mission or update-request context, provider identity, timestamp and assessment outcome. Timeout, rate-limit and invalid-response handling return an unavailable result without changing mission approval. AI output remains advisory.
