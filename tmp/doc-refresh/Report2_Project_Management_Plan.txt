33 [p] 1.2 Project Objectives
34 [p] Deliver a traceable UAV mission-operations platform for planning, pre-flight validation, real-time monitoring, incident management, post-flight review and AI-assisted risk assessment. AI uses a configured external OpenAI or Gemini API; the team implements context preparation, API integration, result display and error handling. Operators and Operations Managers review the advice; approval and operational decisions remain with authorized users. No model training or autonomous flight control is planned.

44 [p] 2. Management Approach
45 [p] The team uses incremental development around four main flows, weekly supervisor meetings, tracking and documented reviews. The controlling timeline is SWP490_Lo-trinh-Capstone_v1.0 (09/2026): Review 1 in W4-W5, Review 2 in W8-W9, Council 1.1 eligibility in W14 and Council 1.2 defense in W15. The SE Capstone Project Review Guideline supplies review content and minutes procedures; its Final Product review content is prepared for the council stage rather than scheduled as an additional W13 review.
46 [p] 2.1 Project Process
47 [p] Four main flows are delivered through three iterations. Iteration 1 completes MF1 Mission Planning & Pre-flight Validation plus shared FE-01 by end W7 as Software Package 1. Iteration 2 in W10-W11 implements MF2 Real-Time Monitoring & Incident Management for Software Package 2. Iteration 3 in W12-W13 delivers MF3 Post-Flight Analysis & Mission History and MF4 AI-Assisted Mission Risk Assessment in parallel, then integrates and system-tests all four flows. Feasibility prototypes in W2-W3 and preparatory design in W5-W6 support the W7 code deadline; W8-W9 accommodates Review 2 and mandatory-feature feedback. Iteration count does not change the four-flow scope.
48 [p] 2.2 Quality Management
49 [p] Quality is managed through prevention, peer review, automated/unit testing, integration testing, system testing and traceability. Definition of Done requires updated documentation, reviewed code, passing tests and demo evidence for each completed main flow.
50 [p] • Defect Prevention: coding conventions, API contracts, architecture/design reviews, reusable validation rules, CI checks and early technical prototypes.
51 [p] • Reviewing: peer review for requirements/design/code; supervisor review at weekly checkpoints; review feedback is logged and closed with evidence.
52 [p] • Unit Testing: core backend services, geospatial validation, incident rules, AI context preparation, response validation and error handling using mocked provider responses.
53 [p] • Integration Testing: simulator/UAV to gateway, telemetry persistence and real-time clients; validation to approval; incident/history/report integration; configured OpenAI or Gemini API success, timeout, rate-limit and malformed-response scenarios. Live API smoke tests complement repeatable mocked tests.
54 [p] • System Testing: end-to-end execution of the four main flows plus critical exception scenarios, latency/reliability checks and regression tests.

Review/council builds are tagged so they can be reproduced.
